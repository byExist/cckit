# Bench

하네스 구성 요소의 변형들을 격리 실행해 계측한다. 품질을 판정하지는 않는다. 판정 기준과 시료는 대상의 tests/에 있고, 이 스킬은 셀별 결과를 나란히 보여줄 뿐이다.

요소마다 주입 경로, 격리 방법, 관찰 채널이 다르다. 대상이 어떤 요소인지 식별하고, 설계 전에 해당 안내서를 반드시 읽는다.

- 스킬·에이전트의 지침 텍스트 → references/skill.md
- 훅 → references/hook.md
- 에이전트의 등록·이름 해석 → references/agent.md
- CLAUDE.md·전역 프롬프트 → references/claude-md.md
- 목록에 없는 요소 → 가장 가까운 안내서를 참고하되, 방법이 검증되지 않았음을 보고에 명시한다

검증 방식은 두 가지다. 인라인 방식은 지침을 서브에이전트 프롬프트에 직접 실어 실행한다. 싸고 병렬로 돌릴 수 있지만 로딩 경로는 검증하지 못한다. 실제 세션 방식은 `claude -p`로 새 세션을 띄운다. 실제 로딩 경로까지 검증하지만 비싸고 호출자 환경을 물려받는다. 어느 쪽을 쓰는지는 안내서를 따른다.

## 설계

1. 시료와 시료별 독자·인자는 대상의 tests/에서 가져온다. 없으면 시료 채집부터 사용자와 정한다. 채집 세션은 호출자의 CLAUDE.md를 물려받아 문체가 오염되니, 유도 없는 평범한 과제로 생성한다. 유도를 실었다면 출처에 기록한다.
2. 축을 정한다: 변형(한 줄이나 블록을 하나씩 뺀 판), 모델, 실행 형태. 기본은 작게, 셀 9개 이하로 잡는다.
3. 셀 수와 예상 토큰(셀당 4만~7만)을 밝히고 실행 전에 확인받는다.

## 실행

안내서의 검증 방식을 따르되, 공통 원칙은 셋이다.

1. 시료는 셀마다 임시 디렉터리에 사본을 만든다. 실행자에게 tests/ 디렉터리를 노출하면 출처와 기대 결과가 새어 나가 실험이 오염된다.
2. 실행자에게는 변형 전문(인라인), 사본 경로, 인자만 준다.
3. 완료 보고에서 셀별 토큰, 시간, 도구 호출 수를 기록한다.

## 판독

1. 결과물은 wc와 diff로 직접 측정한다. 실행자가 스스로 보고한 수치는 믿지 않는다.
2. 표로 보고한다: 셀별 크기 변화, 토큰, 시간, 비용, 결과물 경로. 비용은 실행 시점의 모델 단가를 조회해 근사치로 적는다. 단가표를 미리 박아 두지 않는다.
3. 해석은 판정 없이 호출자에게 넘기되, 실행자가 밝힌 전제, 고민했다는 보고, 예상 밖 수정 같은 셀별 정성 신호는 함께 전달한다. 결과가 결정적으로 보이면 같은 셀을 한 번 더 돌려 보라고 제안한다. 분산 확인에 이보다 싼 방법이 없다.
