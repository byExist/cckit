# Bench

하네스 구성 요소의 변형들을 격리 실행해 계측한다. 품질 판정은 하지 않는다 — 판정 기준과 시료는 대상의 tests/가 소유하고, 이 스킬은 결과를 나란히 놓는다.

요소마다 주입 경로·격리 방법·관찰 채널이 다르다. 대상의 종류를 식별하고, 설계 전에 해당 플레이북을 반드시 읽는다.

- 스킬·에이전트의 지침 텍스트 → references/skill.md
- 훅 → references/hook.md
- 에이전트의 등록·이름 해석 → references/agent.md
- CLAUDE.md·전역 프롬프트 → references/claude-md.md
- 목록에 없는 요소 → 가장 가까운 플레이북을 참고하되, 방법이 미검증임을 보고에 명시한다

릭은 두 종류다. 텍스트 릭(서브에이전트에 인라인 주입 — 싸고 병렬, 로딩 경로는 못 본다)과 실기 릭(`claude -p` — 실제 주입 경로까지 검증, 비싸고 호출자 환경을 상속한다). 어느 릭을 쓰는지는 플레이북이 정한다.

## 설계

1. 시료와 시료별 독자·인자는 대상의 tests/에서 가져온다. 없으면 채집부터 사용자와 정한다. 채집 세션은 호출자의 CLAUDE.md를 상속해 문체가 오염되니, 유도 없는 과제로 생성하고 유도했다면 출처에 기록한다.
2. 축을 정한다: 변형(절제술 — 라인이나 블록을 하나씩 제거), 모델, 실행 방식. 기본은 작게 — 셀 9개 이하.
3. 셀 수와 예상 토큰(셀당 4만~7만)을 말하고 실행 전에 확인받는다.

## 실행

플레이북의 릭을 따르되, 공통 원칙은 셋이다.

1. 시료는 셀마다 임시 디렉터리 사본으로 만든다. 실행자에게 tests/ 디렉터리를 노출하면 출처와 기대 결과가 새어 테스트가 오염된다.
2. 실행자에게는 변형(인라인)·사본 경로·인자만 싣는다.
3. 완료 보고에서 셀별 토큰·시간·도구 호출 수를 기록한다.

## 판독

1. 결과물은 직접 측정한다 — wc와 diff. 실행자의 자가 보고 수치는 믿지 않는다.
2. 매트릭스 표로 보고한다: 셀별 크기 변화, 토큰, 시간, 비용, 결과물 경로. 비용은 실행 시점의 모델 단가를 조회해 근사치로 병기한다 — 단가를 하드코딩해 두지 않는다.
3. 판정 없이 해석은 호출자에게 넘기되, 전제 명시·고민 보고·예상 밖 수정 같은 정성 신호는 셀별로 전달한다. 결과가 결정적으로 보이면 동일 셀 반복을 제안한다 — 분산 확인이 가장 싼 발견이다.
