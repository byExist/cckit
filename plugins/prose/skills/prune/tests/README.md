# 회귀 시료

prune 정의나 pruner 에이전트를 고친 뒤 행동이 달라지지 않았는지 확인하는 고정 시료. 세 장르로 채집해 장르별 판정(섹션·수치·선택지의 생사)이 유지되는지 본다.

## 시료

전부 sonnet이 cckit 리포지토리를 실제로 조사해 생성한 산출물이다 (2026-09-02 채집).

- `exp-a.md` — 온보딩 문서. "처음 접하는 동료에게 소개하는 문서를 작성하라"는 과제. 부풀림 유도 없음. 검증 시 독자: "cckit 플러그인을 이미 설치해서 쓰고 있는 팀 개발자".
- `exp-b.md` — 작업 티켓. mdlint 훅 조사 후 개선 티켓 작성 과제에 "처음 보는 사람도 이해하게 배경·조사 과정·대안까지 꼼꼼히"라는 완전성 요구를 실어 부풀림을 유도했다. 검증 시 독자: "그 작업을 맡아 수행할 mdlint 담당 개발자".
- `exp-c.md` — 조사 보고서. prose 플러그인 현황 조사 과제에 "빠짐없이 상세하게, 검토 과정 포함" 요구를 실었다. 검증 시 독자: "prose 플러그인에 스킬을 추가하려는 팀 개발자".

## 절차

1. 시료를 임시 디렉터리로 복사한다. 이 디렉터리의 원본은 그대로 둔다.
2. 실행자에게는 지침(인라인), 사본 경로, 독자만 준다. 이 디렉터리를 노출하면 시료의 출처와 기대 결과가 새어 나가 테스트가 오염된다.
3. 제거 목록과 고민 보고를 이전 실행 결과와 비교한다.
