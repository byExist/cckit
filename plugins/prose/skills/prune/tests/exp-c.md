# prose 플러그인 현황 보고서

조사일: 2026-09-02
대상: `plugins/prose/` (cckit 리포지토리)

## 개요

prose는 이미 쓴 글을 고치는 두 개의 스킬(`/korean`, `/prune`)과 하나의 에이전트(`rewriter`)로 구성된 플러그인이다.
현재 버전은 작업 트리 기준 `0.7.0`(`.claude-plugin/plugin.json`)이며, 최근 커밋들은 매 변경마다 patch 단위로 버전을 올려 왔다.
`.claude-plugin/marketplace.json`과 루트 `README.md`에 `mdlint`와 함께 등록되어 있어 리포지토리의 정식 플러그인으로 취급된다.

## 디렉터리 구조

```
plugins/prose
├── .claude-plugin
│   └── plugin.json
├── README.md
├── agents
│   └── rewriter.md
└── skills
    ├── korean
    │   ├── SKILL.ko.md
    │   ├── SKILL.md
    │   └── tests
    │       ├── README.md
    │       ├── exp-a.md
    │       └── exp-b.md
    └── prune
        ├── SKILL.ko.md
        ├── SKILL.md
        └── tests
            └── README.md
```

두 스킬 모두 영문(`SKILL.md`)과 국문(`SKILL.ko.md`) 본문을 나란히 두고, 각각 `tests/` 아래 회귀 검증용 README를 둔다는 점에서 구조가 대칭적이다.
차이는 `korean/tests/`에는 회귀 시료 파일(`exp-a.md`, `exp-b.md`)이 실제로 존재하는 반면, `prune/tests/`에는 README만 있고 시료 파일이 없다는 점이다(뒤에서 다룬다).

## 스킬: /korean

- 정의: `skills/korean/SKILL.md`, `SKILL.ko.md`
- 트리거: `/korean [대상]`, `disable-model-invocation: true`로 모델이 자동 호출하지 않고 사용자가 직접 불러야 함
- 동작: 이 세션이 직접 다시 쓰지 않고 `prose:rewriter` 에이전트(새 컨텍스트)에 위임한다. 근거는 "자기가 쓴 문장은 자기 눈에 자연스러워 보인다"는 것과 "세션이 길어지면 원칙이 흐려진다"는 것 두 가지다.
- 절차: (1) 인자 또는 세션의 한국어 산출물로 대상 파일 목록 확정 → (2) diff 기준이 될 원본 확보(git 또는 사본) → (3) 목록 전체에 에이전트 하나만 스폰(파일당 하나씩 띄우지 않음 — 용어 일관성 유지 목적) → (4) 한국어 프롬프트에 파일 경로만 담아 전달
- 검수: 에이전트 완료 후 이 세션이 diff를 확인하되 판단 가능한 범위만 되돌린다 — 뜻/식별자/프로젝트 용어 파손 복구, 에이전트가 보고에 남긴 미해결 해석 확정, 직역 조어 교정. 문장을 다시 쓰지는 않는다(자연스러움 판정은 에이전트 몫으로 못박음).
- 영문/국문 본문은 1:1로 대응되며 내용 차이가 없다.

## 스킬: /prune

- 정의: `skills/prune/SKILL.md`, `SKILL.ko.md`
- 트리거: `/prune [대상] [독자]`, 두 인자 모두 생략 가능, `disable-model-invocation: true`
- 동작: 대상과 독자를 인자 또는 대화 맥락에서 정하고, 글의 종류와 독자가 그 글로 하려는 일을 먼저 판단한다. 산출물은 에이전트 관점에서 쓰이므로 그 일에 쓰이지 않는 내용을 군더더기로 규정한다.
- 군더더기 판정 기준 3가지: 틀렸다는 말을 듣지 않으려 붙인 단서와 예외 / 독자의 판단에 쓰이지 않는 조사·확인 내역 / 독자가 이미 아는 배경.
- 산출: 해당 내용을 제거하고 무엇을 제거했는지 간략히 보고하며, 제거 여부를 고민한 항목도 함께 보고한다.
- `/korean`과 달리 별도 에이전트에 위임하지 않고 호출 세션이 직접 수행한다.

### /prune의 최근 개정 이력 (문서 자체 변경)

`git log`상 prune 관련 커밋 8건이 모두 이 스킬의 본문을 다듬는 데 쓰였다.

가장 최근 커밋(`2120bd1`, 2026-09-02 15:16)의 diff를 보면 본문이 크게 압축되었다.
이전 버전은 "기준은 하나다. 그 독자에게 쓰이는 문장은 남고, 쓴 사람에게 봉사하는 문장은 군더더기다"라는 문장 아래 6가지 군더더기 유형(단서/예외, 조사·확인 내역, 성실해 보이려 세운 섹션·표, 정밀해 보이려 끼운 수치, 권고 없는 선택지 나열, 이미 아는 배경)과 "망설여지는 문장은 없는 셈 치고 본다"는 판정법, 부푼 문단만 새로 쓰라는 지시, 값을 그대로 옮기라는 규칙, 이미 독자에게 전달된 글은 승인부터 받으라는 규칙까지 담고 있었다.
현재 버전은 이를 3가지 유형(단서·예외, 조사·확인 내역, 이미 아는 배경)으로 줄이고, "성실해 보이려 세운 섹션·표", "정밀해 보이려 끼운 수치", "권고 없는 선택지 나열", 값 보존 규칙, 승인 절차 규칙을 모두 들어냈다.
군더더기를 걷어내는 스킬 자신이 매 커밋마다 스스로를 군더더기 제거 대상으로 삼아 온 셈이다.

## 에이전트: rewriter

- 정의: `agents/rewriter.md`
- 이름: `rewriter` (전체 경로는 `prose:rewriter`)
- 용도 명시: "(/korean 스킬 전용) 문서의 한국어를 처음부터 한국어로 쓴 글처럼 다시 쓴다"
- 도구 권한: `Read, Write, Edit` — 대상 파일을 읽고 제자리에서 고치는 데 필요한 최소 권한만 부여
- 모델: `sonnet`
- 지침 핵심: 영어가 아닌 한국어로 사고할 것, 직역 표현·AI 티 나는 표현을 표면만 다듬지 말고 의미를 파악해 처음부터 한국어로 재작성할 것, 문서 구조·격식은 원문을 따르되 문장 짜임새는 원문에 매이지 않을 것, 고유명사·정착 용어·코드·식별자는 보존할 것.
- 예시 두 쌍(before→after)으로 "직역투 교정"의 기준을 구체적으로 제시한다.
- 해석이 갈리는 문장은 고치지 않고 그대로 두되, 보고에 갈리는 해석을 적도록 명시 — `/korean` 스킬의 "검수" 단계가 이 보고를 받아 판정하는 구조와 맞물린다.

## 테스트(회귀 시료) 체계

### korean/tests (완비)

- `exp-a.md`(8줄), `exp-b.md`(5줄): 영어 컨텍스트 위에서 sonnet이 생성한 한국어 산출물로, 전형적인 번역투 파손을 담은 고정 시료(2026-09-01 채집)
- `README.md`: 절차와 판정 기준을 상세히 규정
  - 절차: 시료를 임시 디렉터리에 복사 → 정의 수정 직후라면 반영 지연(약 2분) 대기 후 진단 스폰으로 새 지침 수신 확인 → `prose:rewriter`를 사본 경로만 실어 스폰 → 원본과 diff 대조
  - 판정 기준을 "반드시 잡아야 하는 것(기준선 6/6)", "지켜야 하는 것(위반 시 회귀)", "계약 밖(보너스)" 세 등급으로 나눔
  - 구체적 기준선 수치까지 기록: 2026-09-01~02, sonnet, n=6, 문장 층위 6/6·뜻 보존 6/6·과잉 수정 0건·단어 층위 1/6, 평균 12.4k 토큰

### prune/tests (미완성 — git 미추적 상태)

- `README.md`만 존재(2026-09-02 15:32 작성, 마지막 prune 커밋 15:16보다 뒤)하고, 본문이 언급하는 시료 파일 `exp-a.md`는 디렉터리에 실재하지 않는다.
- README 내용: cckit 온보딩 문서를 sonnet이 "리포지토리를 조사해 처음 접하는 동료에게 소개하는 문서를 작성하라"는 과제로 생성한 자연 발생 산출물(2026-09-02 채집)이라 기술하고, 검증 시 독자를 "cckit 플러그인을 이미 설치해서 쓰고 있는 팀 개발자"로 지정한다고 적혀 있다.
- 절차도 3단계로 정의되어 있다: 시료를 임시 디렉터리로 복사(원본 보존) → 실행자에게는 스킬 본문·사본 경로·독자만 제공(출처 노출 시 오염 우려 명시) → 제거 목록·고민 보고를 이전 실행 결과와 비교.
- 다만 korean/tests와 달리 정량적 기준선(몇 건 중 몇 건 적중 등)은 아직 기록되어 있지 않다.
- `git status`상 `plugins/prose/skills/prune/tests/`는 `??`(전체 미추적)이므로, 이 디렉터리와 README는 아직 한 번도 커밋되지 않은 신규 작업물이다.

## 현재 작업 트리 상태 (커밋되지 않은 변경)

```
 M plugins/prose/.claude-plugin/plugin.json   (버전 0.6.0 → 0.7.0)
 M plugins/prose/skills/prune/SKILL.ko.md
 M plugins/prose/skills/prune/SKILL.md
?? plugins/prose/skills/prune/tests/          (신규, README.md만)
```

`SKILL.md`/`SKILL.ko.md`의 미커밋 변경은 위 "/prune의 최근 개정 이력"에서 설명한 `2120bd1`(마지막 커밋) 이후 아직 커밋되지 않은 추가 편집으로, description을 "이미 써 둔 것에서 부풀린 자리를 쳐낸다" → "산출물에서 불필요한 내용을 걷어낸다"로, 본문 구조를 산문형에서 불릿 목록형으로 바꾸고 있다.
즉 이 변경은 아직 로그에 없는, 진행 중인 다음 개정 단계로 보인다.

## 검토 중 발견한 사항

1. **prune/tests가 미완성 상태다.** README가 참조하는 시료 파일(`exp-a.md`)이 실제로 없어, 지금 이 README만으로는 절차를 재현할 수 없다. korean/tests는 시료·절차·정량적 기준선까지 갖춘 반면 prune/tests는 절차 문서만 앞서 작성된 상태다.
2. **plugin.json 설명 문구가 prune 본문 개정 속도를 따라가지 못한다.** `plugin.json`과 루트 `README.md`는 여전히 "/prune trims what the reader does not need / 독자에게 불필요한 내용을 덜어낸다"는 예전 표현을 쓰는데, 최신(미커밋) SKILL 본문은 "Remove unneeded content from a work product / 산출물에서 불필요한 내용을 걷어낸다"로 무게중심이 "독자 기준"에서 "산출물 자체의 목적 기준"으로 옮겨가는 중이다. 문구 차이가 아직 크지는 않지만 방향성 차이는 있다.
3. **/korean과 /prune의 위임 구조가 다르다.** `/korean`은 별도 컨텍스트의 `rewriter` 에이전트에 실행을 위임하고 호출 세션은 검수만 하는 2단계 구조인 반면, `/prune`은 호출 세션이 직접 판단하고 수행하는 1단계 구조다. 이 비대칭은 의도적으로 보인다 — `/korean`의 근거인 "자기 문장은 자기 눈에 자연스럽다"는 논리가 prune에는 문서상 명시적으로 적용되어 있지 않다.
4. **버전 관리가 매우 세분화되어 있다.** 8개 커밋 모두 prune 본문 수정 + plugin.json patch 버전 증가가 짝을 이루며, 최근 미커밋 변경도 동일한 패턴(0.6.0→0.7.0)을 따르고 있어 다음 커밋에서 동일한 방식으로 반영될 것으로 보인다.
